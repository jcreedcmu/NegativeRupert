## What is being proved

`IsNotRupert.lean` states the goal:

```lean
theorem not_rupert_of_valid_tables
    (table : ChartIndex → AtlasProjectiveSolutionTree.Table)
    (hchart : ∀ chart, (table chart).chart = chart)
    (hvalid : ∀ chart, (table chart).Valid) :
    ¬ IsRupert exactVerts
```

`IsRupert` is the repository's main Rupert predicate (the same one the
Noperthedron theorem uses). `exactVerts` (`Vertices.lean`) is the exact
fivefold-symmetric solid generated by rotating four rational seed vertices
through multiples of 2π/5. The seeds are the published `nopert76.stl`
decimals scaled by (10^15 − 1)/10^15 so that they lie strictly inside the
unit sphere (Rupert is similarity-invariant; the published decimals overshoot
the sphere by about 2e-16). The certificate checkers work on the unscaled
decimals (`stlVertices`); `Approximation.lean` and `TightApproximation.lean`
carry the published-vs-exact error budget. So the theorem is about the exact
symmetric solid, not the literal floating-point STL, exactly as for #214.

The whole Lean theory tree builds with zero `sorry`s:

```
lake build Noperthedron.Nopert76 Noperthedron.Nopert76.NativeExecutable
```

The only missing inputs are the data: valid chart-0 and chart-1 tables.

## Proof architecture

- `Table.Valid` (`AtlasProjectiveSolutionTree.lean`) is a decidable predicate
  over rows. Row kinds: `view_split`, `relative_split`, `edge`, `global`,
  `local`, `symmetry_tube`, `fundamental_prune`, plus the mixed and cone
  variants. Each kind has its own certificate file (`Atlas*.lean`) whose
  soundness theorem is what `Valid` unfolds to.
- Chart-0 `local` rows point into the four shared local-view tables
  (`AtlasProjectiveLocalViewTree.lean`, `SparseLocalViewTree.lean`).
- Two ways to discharge `Valid` on real data:
  1. **Executable** (the plan): `lake exe constructNopert76 <dir>` reads
     `local-view{0..3}.pack` and `chart{0,1,2}.pack`, checks every row with
     native worker tasks (`NativeExecutable.lean`), and builds a value of type
     `¬ IsRupert exactVerts` from the kernel-proved checker specifications.
     Trust is the Lean compiler, as with `native_decide`.
  2. **Generated Lean files**: the #214 emitters in `scripts/nopert214_emit_*.py`
     accept `--namespace` and can write `Generated*.lean` files closed by
     `native_decide` or, in slices, by the kernel. Not yet exercised for #76.
- `checkNopert76Local <pack> <index>` audits one local pack on its own
  (optional de-risking; the constructor re-checks everything). Do not run it
  under `prlimit --as`: it fails with "failed to create thread".

## How to resume

```
sh scripts/nopert76_resume.sh          # launches both searches, detached
python3 scripts/nopert76_status.py     # progress, rates, uncertified volume
python3 scripts/nopert76_status.py --deep   # plus pending-cell autopsy
```

Requirements: Python 3 with `gmpy2` and `numpy`; a Rust toolchain for
`rust/nopert-kernel` (the resume script sets `NOPERT_RUST_KERNEL=1`, which
builds/loads it); Lean via `lake`. The resume script caps chart 0 at 24 GiB
with 11 workers and chart 1 at 36 GiB with 5 workers.

Stopping and relaunching: each generator holds an exclusive `flock` on
`chartN.json.lock` and workers inherit it. After SIGTERM, wait for the lock
before relaunching, otherwise the new run dies with "another generator is
already writing":

```
until flock -n .artifacts/nopert76/chart0.json.lock true; do sleep 5; done
```

Checkpoints are atomic; a kill mid-checkpoint loses at most the rows since
the previous checkpoint. Failures are requeued automatically on resume.

Search-time bugs cannot produce a false proof: Lean re-verifies every row.
They can only make the search fail to terminate or emit rows Lean rejects.

## Endgame

After both charts report `complete: true`:

```
python3 scripts/nopert214_emit_packed_global.py .artifacts/nopert76/chart0.json .artifacts/nopert76/chart0.pack
python3 scripts/nopert214_emit_packed_global.py .artifacts/nopert76/chart1.json .artifacts/nopert76/chart1.pack
lake build constructNopert76
lake exe constructNopert76 .artifacts/nopert76
```

The last command prints progress per table and finishes by constructing the
proof term. For #214 the analogous local-table check ran at roughly 2 hours
per 4,000 local rows, so budget a day or two.

## Code map

Lean (`Noperthedron/Nopert76/`, 35 files, all on the module system):

- `Vertices.lean`: the solid. `Symmetry*.lean`, `FundamentalDomain.lean`,
  `CayleyAtlas.lean`: fivefold symmetry and the four Cayley charts.
- `Certificate.lean`, `LocalCertificate.lean`, `Tightening.lean`,
  `Approximation.lean`, `TightApproximation.lean`: the basic support and
  approximation certificates.
- `Atlas*.lean`: per-row-kind certificates over chart boxes (interval,
  quadratic/Bernstein, edge, global, mixed-global, local, rigidity, view).
- `AtlasProjectiveSolutionTree.lean`: `Row`, `Table`, `Valid`, and the
  theorem that a valid table excludes every pose in its chart.
- `AtlasProjectiveLocalViewTree.lean`, `SparseLocalViewTree.lean`,
  `SparseSupport.lean`: the shared local-view tables that chart-0 tube rows
  reference.
- `PackedSolutionTree.lean`, `PackedLocalViewTree.lean`: decoders for the
  `.pack` format. `NativeExecutable.lean`: parallel checker plus bridge to
  the semantic proof. `FundamentalChart3.lean`: the tiny chart-3 table.
  `GeneratedTangentCones.lean`: emitted by `scripts/nopert76_emit_tangent_cones.py`.
- `IsNotRupert.lean`: the final bridge quoted above.
- Drivers at the repo root: `constructNopert76.lean`, `checkNopert76Local.lean`
  (targets in `lakefile.toml`).

Python (`scripts/`):

- `nopert76_certificate_search.py`: thin wrapper that installs the #76 vertex
  tables into `nopert214_certificate_search.py`, which holds the whole
  engine: atlas subdivision, the escalation menu, checkpoints, resume, worker
  pool. Exact certificate arithmetic lives in `snub_certificate_search.py`.
- `nopert76_status.py`, `nopert76_resume.sh`: operations.
- `nopert76_prune_local_nearby.py`: compaction of a finished local table.
- `nopert214_emit_packed_global.py`, `nopert214_emit_packed_local_view_lean.py`:
  pack emission (vertex-independent, shared with #214).

Rust (`rust/nopert-kernel/`): float screens for the hot path, 3× on chart-0
grinder rows; action stream is sha256-identical to the Python path.

## Gotchas

- The Lean files were copied from `Noperthedron/Nopert214/` with a namespace
  rename. Many docstrings still say "#214"; the code is #76.
- The branch also carries the finished #214 work (Nopert #214 turned out to
  be Rupert: `Noperthedron/Nopert214/RupertWitness.lean`) and the snub cube
  atlas revival (`scripts/snub_atlas_*.py`, `.artifacts/snub/`). Neither is
  needed for #76.
- Chart 0 is the risky chart: the polar view has obstruction rates near 1e-5,
  so its origin tube and razor band needed every escalation kind. Its
  pending cells are shallow far-field bulk plus the eight pole-tipped root
  cells, which will subdivide deep at their tips. That is schedule cost, not
  passage evidence.
- What a passage would look like: a persistent, deepening pending cluster at
  the view-depth cap with `best_c` null in failures. Zero failures so far.
